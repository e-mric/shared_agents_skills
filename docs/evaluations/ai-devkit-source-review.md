# AI DevKit source review

Date: 2026-10-22. Scope: primary-source inspection for the note app’s **imagine → implement → test → review** loop. This is not an executed agent trial or an endorsement of all upstream instructions. No AI DevKit setup, agent startup, messaging, or note-app changes were performed for this review.

## Fit with our four steps

| Portable keyword | Upstream building blocks | Fit and boundary |
| --- | --- | --- |
| Imagine | `dev-requirements`, `dev-design`, `dev-planning` | Requirements, architecture/design-document review and task planning. `dev-design` is not a visual mockup generator; retain our accepted visual-design and image-generation choices separately. |
| Implement | `dev-implementation`, `tdd`, `verify` | Work through accepted plans, check alignment and record evidence. Upstream mandates TDD and frequent phase-document updates; our core should choose verification proportional to the change. |
| Test | `dev-testing`, `verify` | Map tests to acceptance criteria and record fresh results. Keep desktop/mobile interaction checks for the note app; a green unit suite alone does not establish UI quality. |
| Review | `dev-review`, `verify` | Findings ordered by severity, design alignment, changed-code and boundary review. Retain Impeccable for visual/readability review; this skill is mainly a code review. |

These mappings are an adapter design, not built-in aliases or automatic chat routing. Upstream’s `dev-lifecycle` names nine phases plus workspace setup, routes backward on findings, and loads selected phase skills. [Lifecycle](https://github.com/codeaholicguy/ai-devkit/blob/be14ea1e74e6aec24cb156a8d05f50870aa9a426/skills/dev-lifecycle/SKILL.md), [design](https://github.com/codeaholicguy/ai-devkit/blob/be14ea1e74e6aec24cb156a8d05f50870aa9a426/skills/dev-design/SKILL.md), [implementation](https://github.com/codeaholicguy/ai-devkit/blob/be14ea1e74e6aec24cb156a8d05f50870aa9a426/skills/dev-implementation/SKILL.md), [testing](https://github.com/codeaholicguy/ai-devkit/blob/be14ea1e74e6aec24cb156a8d05f50870aa9a426/skills/dev-testing/SKILL.md), [review](https://github.com/codeaholicguy/ai-devkit/blob/be14ea1e74e6aec24cb156a8d05f50870aa9a426/skills/dev-review/SKILL.md), [verification](https://github.com/codeaholicguy/ai-devkit/blob/be14ea1e74e6aec24cb156a8d05f50870aa9a426/skills/verify/SKILL.md).

## Setup and context boundaries

- `setup` is machine-wide: it installs built-in skills/session integrations and wires memory MCP into detected supported agents. `init` is project-level: it writes `.ai-devkit.json`, selected skills/MCP files and phase documents, defaulting to `docs/ai`. It can also initialize Git in a non-repository directory. Test these in a disposable directory before applying them to an existing project. [Getting started](https://github.com/codeaholicguy/ai-devkit/blob/be14ea1e74e6aec24cb156a8d05f50870aa9a426/web/content/docs/1-getting-started.md).
- Config supports `paths.docs`, selected environments/phases/skills and a memory database path. Current Codex project skills use `.agents/skills/`; MCP config uses `.codex/config.toml`. “Ready” environment setup support does **not** imply session discovery or messaging support for every environment. [Config](https://github.com/codeaholicguy/ai-devkit/blob/be14ea1e74e6aec24cb156a8d05f50870aa9a426/web/content/docs/11-configuration-file.md), [environment support](https://github.com/codeaholicguy/ai-devkit/blob/be14ea1e74e6aec24cb156a8d05f50870aa9a426/web/content/docs/2-supported-agents.md).
- `agent list/detail/send` discover sessions, inspect recent context and deliver explicit messages; stdin and waiting for a response are supported. Interactive managed startup defaults to tmux; current docs describe durable mode for Claude, Codex and Pi. This is provider/session control, not a guarantee of separate chats inside desktop applications. The Codex detector expressly excludes `app`, `app-server` and daemon helpers. [Agent management](https://github.com/codeaholicguy/ai-devkit/blob/be14ea1e74e6aec24cb156a8d05f50870aa9a426/web/content/docs/8-agent-management.md), [communication skill](https://github.com/codeaholicguy/ai-devkit/blob/be14ea1e74e6aec24cb156a8d05f50870aa9a426/skills/agent-communication/SKILL.md), [Codex detector](https://github.com/codeaholicguy/ai-devkit/blob/be14ea1e74e6aec24cb156a8d05f50870aa9a426/packages/agent-manager/src/harnesses/codex/CodexAdapter.ts).
- Memory is a searchable local SQLite store, default `~/.ai-devkit/memory.db`, with configurable path and optional local semantic search. Scopes filter knowledge; they do not automatically synchronize databases across machines. The memory skill prioritizes repository evidence over memory and excludes transcripts, task progress, secrets and unverified claims. Keep shared Markdown documents authoritative; use memory as an optional retrieval aid. [Memory skill](https://github.com/codeaholicguy/ai-devkit/blob/be14ea1e74e6aec24cb156a8d05f50870aa9a426/skills/memory/SKILL.md), [config](https://github.com/codeaholicguy/ai-devkit/blob/be14ea1e74e6aec24cb156a8d05f50870aa9a426/web/content/docs/11-configuration-file.md).

## Reuse selectively

Recommended: explicit phase inputs/outputs, return-to-design loops, evidence before completion, discover-before-send and narrowly scoped verified memory. Define our own compact handoff containing goal, accepted design, relevant files/revision, criteria and evidence. Keep existing note-app documents as owners rather than creating competing copies.

Avoid wholesale installation of `dev-lifecycle` as the portable authority: its startup can install **all** built-in skills, uses a Claude-specific fallback initialization command, asks for exact phase approval, and expects its phase-document structure. Its implementation skill mandates TDD. These are upstream policies, not requirements of the user’s portable workflow. Pin the evaluation version rather than embedding its `@latest` commands unchanged. [Lifecycle startup and phase rules](https://github.com/codeaholicguy/ai-devkit/blob/be14ea1e74e6aec24cb156a8d05f50870aa9a426/skills/dev-lifecycle/SKILL.md), [implementation contract](https://github.com/codeaholicguy/ai-devkit/blob/be14ea1e74e6aec24cb156a8d05f50870aa9a426/skills/dev-implementation/SKILL.md).

Proposed boundary: **portable core → optional AI DevKit execution adapter → optional aGiTrack tracking**. This review does not establish an AI DevKit–aGiTrack integration, automatic keyword dispatch, desktop-chat creation, automatic shared transcripts, cost reporting, or model-quality improvements. Those require separate tests or source review. Keep installation, sending work and tracking choices explicit; a manual handoff must remain sufficient.
